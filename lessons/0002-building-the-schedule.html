Building the schedule

How visits get their timing, how phases appear on their own, and how cycles repeat.

Why this matters for the interview Expect a scenario question like "Here's an oncology protocol. How would you build the schedule?" Today's win: turn any protocol schedule of assessments into Vault schedule features (windows, unscheduled groups, cycles and dynamic rules) and explain why each one is there.

Recap from Lesson 1: the schedule is Event Groups → Events → Forms, and only the first Event Group appears in a new casebook by itself. Today we fill in the rest.

1 · What kind of visit is it?

Two properties classify the schedule:Veeva

PropertyOnValues
Event Group TypeEvent GroupEDC (the default, meaning scheduled) or Unscheduled, for ad-hoc visits the protocol doesn't plan
Event TypeEventEDC, Screened, Enrolled, Log

One trap here: "Don't mark Log-type Event Groups as Repeating." Doing that causes a publishing validation error, and the design won't deploy.Veeva

2 · When is the visit due? Event windows

Each Event gets a Planned Date from three properties:Veeva

  • Offset Type: count from a Specific Event, from the Previous Event, or choose None for no window.
  • Offset Days (+ Offset Event Group / Event): how many days after that anchor the visit is due.
  • Day Range Early / Day Range Late: widen the single date into a window.

So "Week 4 is 28 days after Baseline, ±3 days" becomes: Offset Type = Specific Event (Baseline), Offset Days = 28, Day Range Early = 3, Day Range Late = 3. If a site enters an Event Date outside the window, Vault shows a warning. It doesn't block the save.Veeva

3 · How do phases appear? Dynamic rules

Three rule actions build the schedule as the data comes in:Veeva

Rule actionWhen the expression is true, Vault…Typical use
Add Event Groupadds the Event Group to the casebook scheduleShow Treatment once eligibility is confirmed. Show Follow-up after End of Treatment.
Add Eventadds the EventAdd an extra visit only for certain subjects
Add Formadds the FormAdd a pregnancy test only for females of childbearing potential

Veeva's docs call these "dynamic rules" and "Add Schedule-type" rules.Veeva Your Lesson 1 analogue: Rave's add-matrix / add-folder edit checks.

Processing order: a good detail to mention in an interview

After a site completes a Form, Vault runs rules by action type in this order:Veeva

  1. Set Item Value / Set Derived Value
  2. Dynamic rules: Add Event Group, Add Event, Add Form
  3. Query

The reason, in Veeva's words, is so "any Query-type rules that are affected by derived values or any added Event Groups, Events, and Forms can be processed with all expected data present."

4 · Cycles: repeating Event Groups

Tick Repeating on an Event Group, and optionally set a Repeat Maximum. Each repetition is a sequence.Veeva Then:

  • You still need a rule for the first one. "You must create at least one Add Schedule-type rule to add the first repeating Event Group sequence to a Casebook. Data entry users will be able to add subsequent event groups manually." Sites can't go past the Repeat Maximum.
  • Labels. Prefix Label in Related Events is ticked by default, so visits read "Cycle (1) - Visit 1", "Cycle (2) - Visit 1", and so on. Repeating Event Overrides let you give each sequence its own label and its own window.
  • Rules across sequences. Use [2] for a specific sequence, or [-1] / [+1] for the previous or next one with @ identifiers, e.g. @EventGroup[-1].Visit1.event_date__v.Veeva Lesson 3 covers rule syntax properly.
Veeva's own worked example A treatment cycle that subjects complete 3 to 6 times: one repeating Event Group labelled "Treatment Cycle", Repeat Maximum = 6, with Events Day 1 (treatment), Day 8 and Day 15 (follow-up), each holding its Forms. Add one Add Schedule-type rule to surface the first sequence. Sites add cycles 2 to 6 as needed.Veeva Using separate non-repeating groups instead would mean "a large amount of duplicate work" and confused sites.

Practice

Exercise 1 · Protocol → Vault feature

You've been handed this protocol. Pick the Vault feature that implements each requirement.

a. Subjects receive 3–6 chemotherapy cycles, each with Day 1, Day 8 and Day 15 visits.
b. The Follow-up phase must appear only once the End of Treatment form records that the subject completed treatment.
c. A pregnancy test form is collected only for females of childbearing potential.
d. Day 8 must occur 7 days after Day 1, ±1 day, and sites should be warned if it doesn't.
e. Sites must be able to record ad-hoc safety visits that aren't in the schedule of assessments.
f. Cycle 1 should display as "Induction", and Cycle 1's Day 8 window is ±2 days instead of ±1.

Exercise 2 · Quick checks (two are review questions from Lesson 1)

1. "Treatment Cycle" is a repeating Event Group placed after Screening. Before sites can add Cycle 2 themselves, what must exist?

The first sequence is added by an Add Schedule-type rule (e.g. Add Event Group). After that, sites add sequences manually. Repeat Maximum is optional and only caps the number.

2. "Week 4 is 28 days after Baseline, ±3 days." Which properties do you set?

Offset Type = Specific Event (Baseline), Offset Days = 28, Day Range Early/Late = 3.

3. A site enters a Week 4 date outside the window. What does Vault do?

Out-of-window dates trigger a warning. The data still saves.

4. One rule derives Age, one adds an Event Group based on Age, and one queries Age. In which order does Vault process them?

Set/Derived values first, then dynamic rules, then queries, so queries see complete data.

5. Review from Lesson 1. Which record does a subject's entered data actually live on?

Definitions are the template. Vault copies them into execution records in each casebook, and the data lives there.

6. Review from Lesson 1. To show con-meds as an Editable Grid, the Item Group must be…

Grid display formats are available only for repeating Item Groups.

7. Sites need somewhere to record visits the protocol doesn't schedule. Which property handles this?

Set Event Group Type to Unscheduled. The default, EDC, means scheduled.

Exercise 3 · Say it out loud (90 seconds)

"Here's an oncology protocol: screening, then 3 to 6 treatment cycles with Day 1, 8 and 15 visits, then follow-up after end of treatment. Walk me through how you'd build the schedule in Vault."

Compare with a model answer

"I'd create three Event Groups. Screening is first, so it surfaces automatically. Treatment Cycle is a repeating Event Group with Repeat Maximum 6 and Events Day 1, Day 8 and Day 15. Each Event carries a window: Day 8 offset 7 days from Day 1 with a day range of, say, ±1, so sites get an out-of-window warning. I'd write an Add Event Group rule to add the first cycle once eligibility is confirmed on the screening forms. After that, sites add cycles 2 to 6 themselves, and the cap stops a seventh. Follow-up gets its own Add Event Group rule, triggered from the End of Treatment form. I'd also add an Unscheduled Event Group for ad-hoc visits, and conditional forms such as pregnancy tests would use Add Form rules. Because derivations run before dynamic rules and queries, anything like a derived eligibility flag is ready before the schedule rules fire."

Check: repeating Event Group + Repeat Maximum · Add Schedule rule for the first sequence · windows with offset + day ranges (warning, not block) · Add Event Group for follow-up · Unscheduled group. Bonus: processing order.
