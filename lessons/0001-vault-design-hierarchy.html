The shape of a Vault study

You already know how to build a study. This lesson gives you Vault's names for the parts, and the one idea that works differently.

Why this matters for the interview "Walk me through how a study is structured in Vault" is a near-certain opening question. Today's win: you can answer it in about 60 seconds using Veeva's own vocabulary, and place any piece of your old build in the Vault structure.

1 · Two trees, one schedule

Every study design in Vault EDC is built in Studio.Veeva It helps to see the design as two trees joined at the Form:

Veeva's wording: "Each Event represents a visit in your study. Events are grouped into Event Groups."Veeva And on the form side: "On each form, there are a number of Items which represent a question or field. Items are grouped into Item Groups."Veeva You drag and drop the pieces into place in Studio › Schedule.Veeva

Above it all sits the Casebook Definition: one record per version of your design, holding "all the relationships between your study definition object records and data validation rules."Veeva Versioning gets its own lesson later. For now, think of it as "the CRF version".

2 · The idea that works differently: definitions vs execution

Everything you create in Studio is a definition record, even though Studio leaves off the word "Definition" (you see "Form", but you're creating a Form Definition).Veeva When a site creates a subject's casebook, Vault copies each definition into an execution record for that subject:

"Vault creates a copy of your Event Definition record as an Event, or visit, record for each casebook."Veeva

So Screening in Studio is one Event Definition. If 300 subjects are enrolled, there are 300 Screening Event records, one inside each casebook. The data hangs off the execution records. This is why you'll hear Vault people say "definition" and "casebook" so often, and it's the basis for how amendments work in lesson 4.

3 · Three things a newcomer gets wrong

(a) Only the first Event Group shows up by itself

In a new casebook, sites see only the first Event Group. "At a minimum, you must use Add Event Group to surface any Event Groups after the first Event Group in a Study."Veeva So "Treatment" and "Follow-up" stay hidden until a rule adds them. Rules can also surface Events and Forms based on the data entered.

(b) Repetition happens at three levels

LevelSwitchTypical use
Event GroupRepeating, which makes it a CycleVeevaOncology treatment cycles
FormRepeating + Repeat MaximumVeevaOne AE per form instance
Item GroupRepeating + Display Format: Form, Read Only Grid, or Editable GridVeevaCon-med log typed into a grid

Editable Grid works only on repeating Item Groups and can't hold Label items.Veeva

(c) An Item's type decides where its value comes from

Besides plain EDC items, there are Status (changes subject status / sets IDs), Header (shows in the casebook header), Read-only (set by API), and Derived ("set by a rule and will be Read-only in the EDC UI").Veeva Don't name items with reserved words such as Subject ID, Event Date, Site. Vault already captures these and they break SAS conversion.Veeva

Exercise 2 · Interview-style checks

1. In Vault EDC, what is the direct parent of an Item?

Forms contain Item Groups, and Item Groups contain Items. A Codelist hangs below an Item, as its list of choices.

2. Your design is published. A site creates subject 101-001. What does Vault create for that subject's Screening visit?

At casebook creation, Vault copies the Event Definition into an Event (execution) record for that casebook.

3. Your schedule has Screening, Treatment and Follow-up Event Groups and no rules yet. What does a site see in a new casebook?

Event Groups after the first must be surfaced with an Add Event Group rule. Building that rule is a classic first task.

4. The protocol has a 28-day treatment cycle that repeats up to 12 times. What models it?

A repeating Event Group is what Vault calls a Cycle. Each cycle holds its own visits (Events).

5. Sites want to type con-meds into a table, both while editing and after submitting. Which setting do you use?

Editable Grid shows the repeating Item Group as a grid in both Edit and Submitted states. Read Only Grid shows a grid only after submission.

6. BMI must be calculated from height and weight and must not be editable by sites. Which Item Type?

A Derived item's value is set by a rule and is read-only in the EDC UI.

7. Your first casebook version is published and the protocol is amended. In Studio, what's your first step?

Publishing makes definitions read-only (rules excepted). Changes go into a new Casebook Definition version. Lesson 4 goes deeper.

Exercise 3 · Say it out loud (60 seconds)

Set a timer. Without looking, answer this aloud as if you're in the interview:

"How is a study design structured in Vault EDC, and how does it turn into a subject's casebook?"

Compare with a model answer

"In Vault you build in Studio. The design is a Casebook Definition, one per version, holding a schedule of Event Groups, which contain Events (the visits), which contain Forms. Each Form has Item Groups, and Item Groups have Items, which can use Codelists and Units. Everything in Studio is a definition. When a site creates a subject, Vault copies those definitions into execution records in that subject's casebook. Only the first Event Group appears automatically, so later ones are surfaced with Add Event Group rules. Repetition can be at the Event Group level for cycles, the Form level, or the Item Group level, which can be shown as an editable grid. Coming from Rave, it's the matrix-and-folder model, but with an explicit definition/execution split and versioned casebook definitions."

Check: did you mention (1) the hierarchy, (2) definition → execution copy, (3) Add Event Group? Those three are what set you apart from someone who only read a brochure.
